# 需求与实现边界

## 背景与目标

Dayi 是 macOS 菜单栏应用，在其他应用的可编辑输入区提供选中文本、快捷键触发、原位替换与专用撤回。项目只交付 macOS App，不提供命令行润色入口、外部编辑器会话集成或独立 SDK；PolishCore 与 PolishStore 仅作为应用内部模块。

产品目标是忠于原意、改善表达。当前默认模板按 Dayi 需求独立编写；编辑草稿而不执行草稿请求，保留原意、语言与约束。分级增强及额外上下文提供仍留待后续讨论。

## 已明确的需求

| 编号 | 要求 | 验收关键点 |
|---|---|---|
| U-01 | 在 macOS 应用中使用独立的润色工具 | Dayi 能通过用户配置完成真实模型请求 |
| U-02 | 全局快捷键捕获用户选区 | 有选区只取选区；无选区时全选当前输入区（2026-09-10 起），不猜测其他控件；空输入区明确提示 |
| U-03 | 原位替换并支持撤回 | 改写原选区，保留范围外内容，冲突时拒绝 |
| U-04 | 处理状态不受焦点切换影响 | 任务继续、目标绑定不变，不误写新焦点 |
| U-05 | 支持返回原上下文 | 用户主动恢复原应用、窗口与可确认的输入位置 |
| U-06 | 仅交付 macOS App（2026-09-11 范围收敛） | 构建、打包、文档仅提供 App；不再包含 CLI 产品与会话脚本 |
| U-07 | 必须自动写回原位置，且不抢占当前焦点 | A 后台变更，B 的焦点、光标与继续输入保持；保留结果待用户返回不算完成 |

## 系统边界

本机用户触发操作；Dayi 负责捕获、生成、目标验证、回写、回读、撤回与状态显示；模型服务仅负责返回文本。目标客户端负责自身草稿、附件、会话与提交。

模型凭据来自用户在 App 中保存的设置与钥匙串，或显式进程环境；辅助功能权限由 macOS 控制。Dayi 不提供多用户权限系统，不自动读取目标会话历史，也不自动提交草稿。

## 核心流程与数据

1. 捕获原目标、文档快照与 UTF-16 选区，拒绝空白或无法确认的可编辑选区。
2. 创建独立任务，用当前版本的默认模板与选中文字调用配置的模型。
3. 结果有效后检查原目标和原文；支持后台写入的适配器自动写回，否则保留结果。
4. 核验实际正文；状态区分生成完成、受阻、应用中、已应用、不确定与已撤回。
5. 撤回按原快照、已插入文本和受保护前缀判断，允许已实现范围内的后缀编辑，冲突时保留现状。

主要模型：TextSnapshot（正文、范围）、PolishJob（任务身份、计算与应用状态、结果）、TextTarget（目标身份与读写接口）、AppliedEdit（原快照、结果及撤回范围）。润色历史保存在本机数据库；AX 目标和原位撤回数据只保留在当前进程内存中。

## 当前缺口

真实 Codex／Claude 桌面的无焦点后台回写尚缺可用宿主入口。此前检查的普通调试启动、AX 范围替换、深链接、MCP 插件及对话服务接口不能直接证明满足 U-07。需要可靠的文档身份、不聚焦的编辑事务及宿主状态回读。

其他未完成项包括终端子串、真实富文本和附件保真、文档重建与完整生命周期验收、输入法组合态、最低系统兼容性以及正式发布基线。用户确认阶段性开发结束并要求整理发布仓库，并不等于这些功能已实现。
