# 网页来源与写作场景：讨论稿

2026-09-11 初稿。用户已明确同时需要按网站整理历史和按写作场景调整润色，并要求调研核心场景，而非预先指定网站。

最新范围：用户已将 prompt 迭代 park，优先授权浏览器／网站来源识别。当前只实现来源捕获、历史与界面筛选，见 [浏览器来源实施记录](browser-source.md)；下文的写作场景路由、用户纠正和模板选择仍是讨论项，未接入应用。

## 目标

同一浏览器中的不同来源可识别、可筛选；同一段草稿按实际沟通目的改善表达，避免所有输入都使用当前的编程提示词增强模板。网站身份与写作场景分别记录，不把网站名等同于用户意图。

## 核心场景建议

这是结合产品能力与写作差异的优先级建议，不是用户使用频率统计，也不表示所列网站已通过写回验收。

| 场景 | 代表页面 | 润色目标 | 不应自动发生 |
|---|---|---|---|
| AI 指令 | ChatGPT、Claude、Gemini | 明确目标、约束、输出要求；保留用户意图 | 新增技术选型、实施范围、虚构上下文；替用户回答指令 |
| 邮件 | Gmail、Outlook | 请求清楚、语气得体、结构顺畅 | 编造收件人、日期、附件、承诺；读取整个邮件线程 |
| 即时工作沟通 | Slack、Teams、飞书 | 简短、自然、可执行，保留说话口吻 | 自动变正式公文、加称呼落款、扩大承诺 |
| 问题与任务反馈 | GitHub、Linear、Jira | 分清现象、预期、已有复现步骤与请求 | 编造复现步骤、版本、根因、优先级或负责人 |
| 文档与说明 | Notion、Google Docs | 改善段落逻辑、术语一致性和可读性 | 擅改事实、引用、代码块和文档结构 |
| 通用表达 | 未识别的网站与普通表单 | 保守改善表达，保留语言与语气 | 把未知输入自动当成开发指令 |

社会化发布、营销、求职等有价值，但第一版建议暂用通用模式，避免一次建立过多未经验证的风格模板。

## 官方来源与推导

- [OpenAI 的提示词建议](https://help.openai.com/en/articles/10032626)：清晰、具体和足够上下文是指令质量的基础；Dayi 只整理已有信息，不编造缺失上下文。
- [Gmail 的草稿润色](https://workspaceupdates.googleblog.com/2024/08/refine-emails-faster-with-help-me-write-gmail.html)：正式化、扩写、缩短与润色是不同操作；本产品默认仍是保留原意的润色，不根据网址擅自扩写。
- [Notion 的文档写作编辑](https://www.notion.com/help/guides/notion-ai-for-docs)：语气、语法与文档编辑是明确用途；不能由此推断其复杂编辑器已能通过 Dayi 的 AX 路径安全写回。
- [GitHub 的问题表单](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms)：预期行为与复现步骤有明确结构；空缺事实应保留空缺。

## 范围与关键约束

1. 复用捕获时已有的 AXWebArea URL。来源标签与实际宿主 bundle 身份分开，避免改标签后破坏返回应用。网页标题、正文不是默认额外采集项。
2. 第一版按已核实的域名／路径匹配默认场景；允许用户纠正。AI 助手嵌在文档或协作工具里时，不能仅凭顶层网站判断为普通文档／消息，应能覆盖或退回通用模式。
3. 原始 URL 与 AX 句柄用于内存中的目标校验；历史默认仅增加来源标识、场景与规则版本，不保存可能带令牌的完整网址。旧记录来源未知，不倒填。
4. 触发时固定目标、场景和模板；之后换标签页、改场景或切模型，都不改变在途任务。UTF-16 校验、写后回读、不确定结果不重试、不自动发送保持现有约束。
5. 界面语言与输出语言独立；输出继续匹配输入。只润色当前选区／既有无选区捕获范围，不读取整页、聊天历史或附件。
6. 场景支持与编辑器兼容分别验收。Google Docs、Notion、跨段富文本等先验证可读选区、稳定范围、写后回读，再声明支持；当前多段限制不因网站规则而放开。

## 预期结果与完成标准

- 历史可区分同一 Chrome 中不同网站，按网站与场景筛选；有事实依据的来源与未知来源清楚区分。
- 每个首批场景用中英合成草稿对比：用户事实、约束与语言保留，表达更清晰，无未授权扩写。
- 同网站不同输入用途、iframe、SPA 导航、切标签页与未知域名有明确测试；不会写入新焦点。
- 用户能解释本次采用的场景并纠正后续默认行为；纠正不能修改已完成历史事实。

尚待讨论：首批启用哪些场景；用户纠正是只影响本次还是记住网站默认；识别不确定时直接用通用模式还是让用户先选。讨论完成前不改现有模板和捕获链路。
